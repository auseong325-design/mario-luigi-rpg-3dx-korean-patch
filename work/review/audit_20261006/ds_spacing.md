# DS 동일 대사 내부 공백 전수 감사 — 2026-10-06

기존 본편 감사에서 공백을 제외한 글자·문장부호가 DS와 같다고 분류한 2,870개 전부를 보완 검토했다. 샘플 검사가 아니라 해당 일치 그룹 전체의 문자 경계를 정렬했다. 서브에이전트는 번역 파일을 수정하지 않고 후보와 검증 결과를 보고했으며, 메인 에이전트가 아래 8개를 직접 검토해 반영했다.

## 방법과 범위

`ds_field_before_rows.json`의 `exact=true` 2,870개를 기준 집합으로 삼고, 각 ID의 현재 `text/ko` 번역을 다시 읽었다. DS와 KO에서 제어태그를 제외하고 `[Next]`를 줄바꿈 경계로 취급했다. 비공백 문자열이 같은 것을 확인한 뒤 인접 문자 사이마다 원래 공백을 보관해 대조했다.

한쪽이라도 줄바꿈이 있는 경계는 문장을 3DX 폭에 맞춰 다시 감싼 것으로 간주해 제외했다. 처음·끝의 들여쓰기와 끝 공백도 내부 띄어쓰기 검토에서 제외했다. 양쪽 모두 줄 안에 있는 경계에서만 공백이 다르면 후보로 기록했다. 숨겨진 선택지 간격 태그를 제거했을 때 생기는 차이는 원 태그를 다시 읽어 오탐으로 판정했다.

「할 수→할수」처럼 일반어 띄어쓰기가 새로 손상된 사례는 없었다. 발견한 차이는 제어태그 표현, 이미 기록된 DS 오기 수정, 일반 스타일 권고를 DS 동일 문장에도 적용한 흔적, 문장 중간 pause의 시각적 간격이었다.

기존 R13은 화살표를 붙이는 일반 스타일을 우선했고, `o_ekubon_02#0` notes에는 실제 붙인 결과와 「DS대로 띄어 둠」 설명이 서로 달랐다. AGENTS 0·4.6과 style_guide 첫머리는 같은 뜻의 DS 문장을 그대로 사용하도록 하므로 이번에는 DS 간격을 복원했다. 메인이 `text/style_guide.md` 2.1의 화살표 규칙도 「같은 DS 표지판의 공백은 원문 그대로, 신규 표지판은 붙임 권고」로 명확히 했다.

후보 8개의 태그를 포함한 제안 문자열을 실제 번역 파일에 쓰지 않고 `merge_ko.check_message()`로 검사했을 때 오류 0·경고 0이었다. 메인 반영 후 전체 2,870개를 다시 검사해 복원 대상 8개의 차이가 사라진 것을 확인했다. 메인의 최종 `check_final.log`는 130배치 전체 오류 0이다.

이처럼 공백을 제외한 문자열이 같아도 DS의 다른 장면이나 구호와 자동으로 연결될 수 있으므로, 문자 정렬만으로 DS 의미·말투가 같다고 단정하지 않았다. 18개 후보 전부 일본어, DS, 현행 용어집과 가이드 및 기존 notes를 직접 판정했다.

## 산출물

- `ds_spacing_summary.json`, `ds_spacing_candidates.json/tsv`: 반영 전 2,870개 정렬 집계와 후보 18개 전문.
- `ds_spacing_evaluated.tsv`: 18개 후보 전부의 유지/복원 판정과 이유.
- `ds_spacing_proposals.json`: 태그를 보존한 제안 번역 8개 및 읽기 전용 검증 결과.
- `ds_spacing_after_summary.json`, `ds_spacing_after_candidates.json/tsv`: 메인 반영 후 전수 재검사 결과. 남은 10개는 위의 유지 유형뿐이다.
- 메인 기록 `ds_spacing_changes.json`, `ds_spacing_backup/`, `apply_spacing.py`: 실제 반영 8개와 백업.

이 보완 감사에서 서브에이전트가 직접 쓴 파일은 위 검토 폴더의 helper·보고서·대조 자료뿐이다. 원본·번역·전역 파일의 실제 수정은 메인이 검토 후 수행했다.

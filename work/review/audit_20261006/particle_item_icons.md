# HB particle 및 이벤트 아이콘 추가 감사 (2026-10-06)

## 결론

- `HB/particle.ptcl.z`의 텍스처 **87개 기본 레벨 + 하위 mip 7개 = 그림 94개**를 전부 추출하고 직접 확인했다. 불꽃·연기·번개·충격·물방울·나무·지형 등의 그림이며, 글자와 일본어는 발견하지 못했다. 이 파일의 그림에 추가 한글화 작업은 필요하지 않다.
- 기존의 「51개 텍스처」 추정은 헤더 오독이다. `SPBD` 뒤 `0x33`은 **버전 51**이다. 실제 효과 묶음은 322개, 이미터는 849개, 비어 있지 않은 텍스처 참조는 866개이며, 서로 다른 저장 위치의 텍스처는 87개다.
- `m_item_ev_all`의 검토 대상 11칸은 **일본어 6칸 + 숫자만 있는 5칸**이다. 대응 아이템의 메뉴 이름·설명 및 메뉴 코드의 리소스 호출은 확인했지만, 일본어 임시 프레임이 실제 플레이 중 표시되는지는 확정하지 못했다. 「미사용」으로 단정하지 않고 게임 확인 대상으로 남긴다.
- 원본과 패치 파일을 수정하지 않았다. 분석 helper·로그·PNG·보고서는 모두 `work/review/audit_20261006/` 안에만 만들었다.

## particle 검증 근거

입력 `particle.ptcl`은 2,491,624바이트다. `lib3dx.romfs_path('HB/particle.ptcl.z')`로 읽은 실제 원본을 기존 `libhb.unpack()`으로 다시 풀어 입력과 바이트 전체가 같은지 확인했다.

| 항목 | 확인값 |
|---|---|
| 압축 원본 SHA-256 | `c0dc735fdf5be978696a0a1ff9e908ab0873cc06f81396c0dd5530594af02f02` |
| 압축 해제 SHA-256 | `447e44afedb893aeecb9d3663639791f87bf41f5d7c3064e44bebda7e9d3c935` |
| magic / version | `SPBD` / `0x33` (51) |
| 효과 묶음 수 | 322 (`0x08`의 u32) |
| 이미터 수 | 849 (모든 효과 묶음의 이미터 수 합계) |
| 텍스처 참조 수 | 866 (이미터별 최대 2개 슬롯, 비어 있는 슬롯 제외) |
| 텍스처 저장 영역 | `0x11C380`~`0x225E80` (끝 주소 제외) |
| 텍스처 저장 영역 크기 | 1,088,256바이트 (`0x109B00`) |
| 서로 다른 저장 위치 | 87개 (동일 offset의 참조 통합) |
| 기본 레벨 / 추가 mip | 87 / 7 |
| 전체 크기 설명 | 1,088,256바이트; 빈 구간 0개, 겹친 구간 0개 |
| 일본어 및 다른 글자 | 0개 발견 |

형식 해석은 [Switch-Toolbox의 PTCL_3DS.cs](https://github.com/KillzXGaming/Switch-Toolbox/blob/master/File_Format_Library/FileFormats/Effects/PTCL_3DS.cs)를 참조했다. 위 헤더·효과 테이블·이미터 포인터·텍스처 descriptor의 구조를 로컬 바이너리 전체에서 교차 확인했다. 외부 코드를 복사해 실행한 것이 아니라, 형식 정보를 바탕으로 읽기 전용 helper를 작성했다.

- 효과 테이블: `0x48`부터 28바이트짜리 레코드 322개. 각 레코드의 이름 오프셋, 이미터 수 및 이미터 포인터 테이블을 읽었다.
- 이미터의 `+56`은 이름 오프셋, `+64`부터 124바이트 descriptor 2개다. 각 descriptor의 너비·높이, mip 수, surface format, 데이터 크기·영역 내 오프셋을 읽었다.
- 포맷 enum을 기존 `libtex3ds` 이름으로 연결해 디코드했다. ETC1 / ETC1A4 / LA4 / LA8 / L8 / RGBA4가 실제 자료에 있다.
- 각 이미지의 크기가 기본 및 하위 mip의 포맷별 필요 바이트 합계와 같은지 확인했다. 동일 offset를 참조하는 모든 descriptor의 크기·포맷·mip 수가 같은지 확인했다. 모든 범위가 텍스처 영역 안에 있고, 정렬된 구간 합계가 영역 전체를 정확히 덮는다.
- 대조표 `particle_sheet_00.png`~`particle_sheet_05.png`에서 기본 레벨 87개를, `particle_mips.png`에서 하위 mip 7개를 전부 직접 확인했다. 메인 에이전트도 동일 7개 대조표를 직접 보고 글자 없음에 동의했다.

산출물은 `particle_manifest.json`(offset·크기·포맷·SHA-256·참조하는 효과/이미터), `particle_textures/`(94개 PNG), `particle_extract.py`, `particle_extract.log`다. 재실행은 루트에서 다음과 같이 timeout wrapper를 사용한다.

```powershell
.venv\Scripts\python.exe -X utf8 work/review/audit_20261006/run_checked.py particle_extract 120 work/review/audit_20261006/particle_extract.py
```

이 감사는 텍스처 추출과 글자 검토다. 322개 효과의 모든 동작을 게임에서 재생하거나 입체 도형·셰이더를 완전히 복원한 것은 아니다. 추출된 그림 전체와 저장 영역에 대해서는 누락이 없다.

## m_item_ev_all 11칸의 정확한 내역

`work/img/obj/3DX/Menu/m_item_ev_all/f*.png` 및 원본 대조표 `work/img/review/I3_survey_3DX_Menu_00.png`를 확인했다. 객체는 애니메이션 46개·프레임 46개이며, 각 애니메이션은 프레임 1개다. 아래 번호는 I3에서 지정한 짝수 프레임이다. 홀수 짝은 그림 저장 영역을 공유하고 위치가 달라지는 배치이며, 11칸이라는 집계는 같은 그림의 짝을 제외한 집계다.

| 프레임 | 그림에 보이는 내용 | 판정 |

원작 데이터의 임시 그림이라는 형태상 추정은 타당하지만, 형태만으로 실제 미사용을 증명하지는 못한다.

### 메뉴 연결에서 확인한 근거

1. 3DX의 `text/jp/Menu.json`에는 `MES_MenuMes_EventItemN_*` 이름과 `MES_MenuMes_EventItemE_*` 설명이 실제로 있다. `birinpa`의 메뉴 이름은 `ビリビリンパ`로, 임시 그림의 축약 손글씨 `ビリリンパ`와 약간 다르다. `vacuum_blk`, `starvaccine_r/y/g`, `mkiller`도 모두 있다. 이벤트 아이템 메시지 67개를 `item_event_messages.json`에 읽기 전용으로 모았다.
2. v1.2에서 사용되는 `romf2/RO/MainMenu.cro`에 `m_item_ev_all` 문자열이 `0x1DF80`에 있으며, ARM 코드 `0x1DE04`의 `ADR` (`0xE28F3F5D`)가 이 주소를 읽는다. 따라서 리소스 이름이 단순 문자열 잔재로만 있는 것은 아니다.
3. CRO 내부 재배치 테이블을 [Azahar의 CRO 구조](https://github.com/azahar-emu/azahar/blob/master/src/core/hle/service/ldr_ro/cro_helper.h)에 따라 읽어 이벤트 아이템 표의 이름·설명 포인터 연결을 확인했다. 코드/ROData/Data 구간과 재배치 레코드 1,784개를 읽었으며, 해당 이름·설명 문자열로 향하는 내부 재배치가 실제로 존재한다.

| 아이템 표 행 주소 | 아이템 값 | 이름 / 설명 라벨 |
|---|---|---|
| `0x24C70` | `0xC141` | `N_vacuum_blk` / `E_vacuum_blk` |
| `0x24C84` | `0xC142` | `N_birinpa` / `E_birinpa` |
| `0x24C98` | `0xC143` | `N_mkiller` / `E_mkiller` |
| `0x24CC0` | `0xC145` | `N_starvaccine_r` / `E_starvaccine_r` |
| `0x24CD4` | `0xC146` | `N_starvaccine_y` / `E_starvaccine_y` |
| `0x24CE8` | `0xC147` | `N_starvaccine_g` / `E_starvaccine_g` |

이 표에는 빨강·초록·파랑 열쇠, 스타패널, 치료약, 블로캣, 직소 퍼즐 조각 등의 다른 실제 아이템도 있다. 따라서 이름·설명의 존재를 근거로 해당 임시 그림을 곧바로 「미사용」 처리할 수 없다. 반대로 표의 값을 프레임 번호로 잘못 읽어 「일본어가 반드시 노출된다」고 단정할 수도 없다.

### 확인하지 못한 부분과 게임 확인 항목

아이템 표의 각 값에서 실제로 선택하는 Obj 프레임 번호로 이어지는 실행 경로와, 이벤트의 획득·소비 조건까지는 검증하지 못했다. 숫자 1~5 임시 그림은 연결되는 실제 아이템을 찾지 못했다. 코드 내부 표에 같은 개수가 있다는 정도의 추정은 근거로 사용하지 않았다.

게임에서는 **중요 아이템 메뉴**에서 비리비린파/배큐엄 블록/스타백신 3색/매그넘킬러를 보유한 장면의 아이콘을 확인할 필요가 있다. 잠깐만 보유하거나 획득 직후 소비되는 아이템이면 획득 전후 이벤트에서도 확인한다. 일본어 6개 그림이 실제 나타나면 정식 아이콘으로 대체하거나 1DX·DS 문체에 맞춘 한글 그림을 만든다. 숫자만 있는 5개 그림은 자체적으로 일본어 미번역은 아니며, 노출 여부와 용도를 먼저 확인한다.

관련 로그: `item_probe.log`, `item_xref.log`; 구조화한 참조: `item_xrefs.json`, `item_icon_pairs.json`. 후자의 11개 쌍 모두 같은 픽셀 버퍼/크기/뒤집기 값이며, 짝수 프레임은 y=12, 홀수는 y=0인 것을 확인했다. 원본 또는 `patch/` 수정은 하지 않았다.
